# 관문키트 v2

AI 에이전트에게 코딩을 시킬 때 쓰는 운영 절차와 그것을 강제하는 게이트.

**이 키트가 하는 일은 하나다. 에이전트의 "완료했습니다" 를 판정 근거에서 제거하고, 단계를 닫을
자격을 코드베이스에서 기계로 확인되는 증거로만 결정한다.** 나머지는 전부 그 원칙의 구현 세부다.

이것은 **래칫이지 판사가 아니다.** 뒤로 미끄러지는 것을 막는다. 산출물이 맞다고 말해주지 않는다.
v1 을 한 사이클 완주한 결과, 게이트가 PASS 를 낸 상태에서 사람이 결함을 찾은 것이 네 번이다.
**정확성은 사람이 판정한다.**

---

## 15분 안에 시작하기

```
1. 이 폴더를 프로젝트 루트에 복사한다
2. node -v            (18 이상)
3. git init; git add -A; git commit -m "chore: 키트 기준선"; git tag green/day0
4. node scripts/gate.mjs           <- FAIL 이 정상이다. 명세가 비어 있다
5. node scripts/gate-selftest.mjs  <- PASS 여야 한다. 아니면 게이트를 믿지 마라
6. SPEC.md 를 채운다               <- 여기가 가장 값이 큰 40분이다
```

설치 판정은 이렇게 움직인다.

| 시점 | 결과 | 이유 |
|---|---|---|
| 갓 설치 | FAIL | 명세가 비었다 |
| SPEC 채우고 러너 세운 뒤 | PARTIAL (exit 3) | 아직 회귀 항목이 없다 |
| 첫 회귀 항목 등록 뒤 | PASS (exit 0) | 여기서부터 통과가 근거를 갖는다 |

**PARTIAL 은 통과가 아니다.** SKIP 은 '검사하지 못했다' 는 뜻이다.

자세한 절차는 `RUNBOOK.md`. **처음이면 그 파일부터 읽어라.**

## 파일 지도

| 파일 | 무엇 | 누가 고치는가 |
|---|---|---|
| `RUNBOOK.md` | 절차. 설치부터 단계 마감까지 | 사람 |
| `AGENTS.md` | 에이전트가 매 세션 읽는 규약 | 사람 |
| `PROMPTS.md` | 복붙용 프롬프트 11개 | 사람 |
| `SPEC.md` | 요구 목록. R-ID 와 검증 기준 | **사람만** |
| `PROGRESS.md` | 진행 상태. 컨텍스트가 날아가도 남는 진실 | 모델이 갱신, 사람이 확인 |
| `REGRESSION.md` | 한 번 동작한 것의 원장 | 모델이 제안, 사람이 붙여넣기 |
| `ISSUES.md` | 미해결 문제 원장 | 모델이 적고, **사람만 닫는다** |
| `CHECKS.md` | 눈으로만 판정되는 것의 기록 | **사람만** |
| `scripts/gate.mjs` | 게이트. 검사 8개 | **사람만** |
| `scripts/gate-selftest.mjs` | 게이트를 검사한다 | **사람만** |
| `CHANGES-v2.md` | v1 에서 무엇이 왜 바뀌었는가 | 사람 |

`AGENTS.md` 는 `CLAUDE.md` 나 `GEMINI.md` 로 이름만 바꿔도 그대로 적용된다.

## 게이트

```
node scripts/gate.mjs
```

종료 코드가 판정이다. `0 = PASS` / `1 = FAIL` / `2 = 실행 불가` / `3 = PARTIAL`.
**커밋해도 되는 것은 0 뿐이다.**

검사 8개에 등급이 붙어 있다.

**확정** — selftest 를 통과하고, **v1 미션에서 실제로 울려 무언가를 막은 것이 관측됐다.**
`tests`(빌드·테스트) · `regression`(회귀 재확인) · `blockers`(열린 blocker).

**유예** — selftest 는 통과하지만 실전에서 울린 기록이 없다.
`worktree` · `bypass` · `test_tamper` · `unassigned_rid` · `manual_checks`.

유예 검사가 다음 사이클에서도 울리지 않으면 뺀다. **울리지 않는 검사는 통과에 근거를 보태지
않으면서 매 단계 비용만 먹는다.**

### 게이트를 고쳤으면 selftest 를 다시 돌린다

```
node scripts/gate-selftest.mjs
```

검사마다 위반 상태를 만들어 **민감도**(위반을 만들면 FAIL 이 나오는가)와
**특이도**(정상 상태에서 조용한가)를 판정한다. 단계마다 돌지 않는다 — `gate.mjs` 가 바뀔 때만이다.

**v1 에서 8개 중 2개가 죽은 채 PASS 를 내고 있었다.** 게이트가 스스로 신고하지 않았고 사람이
우연히 스크립트를 읽어보고서야 발견했다. 이 파일이 그 구멍을 닫는다.

## 이 키트를 쓸 때 가장 많이 틀리는 것 셋

**게이트 PASS 를 "산출물이 맞다" 로 읽는 것.** 게이트는 증거의 형식을 본다. 내용이 옳은지는 모른다.

**검증 기준을 기계가 못 재는 문장으로 쓰는 것.** "휴대폰과 대조한다", "자연스러워 보인다" 같은
기준은 자동 감사에서 **조용히 다른 기준으로 대체된다.** v1 에서 실제로 일어났다.
기계가 못 재는 것은 버리지 말고 `CHECKS.md` 로 보내라.

**깨질 것 같은 자리를 안 만들어보는 것.** v1 의 네 발견 전부가 "일부러 만들어본" 데서 나왔다 —
행의 첫날·마지막날·말일에 각각 일정을 넣어본 것, 경계 날짜를 하나씩 밟아본 것.

## 아직 안 된 것 — 정직하게

- **비결정 영역이 비어 있다.** 이 키트 전체가 "이걸 하면 이게 보인다" 는 재현 가능성을 전제로 선다.
  에이전트의 출력 품질처럼 두 번 돌리면 다른 것에는 회귀 항목이 아니라 **eval set** 이 필요하다.
  그 층은 없다. 실제로 돌려보기 전에 상상해서 쓰지 않는다.
- **큰 코드베이스에서 시험되지 않았다.** v1 의 관측은 요구 7개짜리 단일 파일 프로젝트에서 나왔다.
  사람이 전부 지켜볼 수 있는 크기였다. 그 조건에서 게이트의 한계 기여는 "주의 깊은 사람 한 명" 을
  넘지 못한다. 래칫이 값을 하는 자리는 사람이 다 못 지켜보는 크기인데, 거기서는 아직 모른다.
- `WHY.md`(해석) 와 `EXAMPLES.md`(채워진 예시) 가 없다. 미룬 이유는 `CHANGES-v2.md` 에 적었다.
  예시가 필요하면 `scripts/gate-selftest.mjs` 의 정상 픽스처를 보라 — 형식이 전부 맞고 게이트가
  exit 0 을 내는 작동하는 프로젝트다.
