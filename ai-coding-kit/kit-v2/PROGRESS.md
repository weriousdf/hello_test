# PROGRESS — 진행 상태

컨텍스트가 날아가도 살아남는 유일한 진실. 모델의 이전 보고문은 근거가 아니다.
모델은 작업 1개를 끝낸 직후 이 파일을 갱신한다. 증거 확인은 사람이 한다.

**여기에 적는 것은 이미 일어난 일만이다. 아직 찍지 않은 태그나 끝내지 않은 단계를 적지 않는다.**
**단계 번호를 앞질러 바꾸지 않는다. 단계는 사람이 green 태그를 찍은 뒤에만 넘어간다.**

> 위 두 줄은 장식이 아니다. v1 에서 모델이 존재하지 않는 `green/stage3` 태그를 이 파일에
> 적었고 단계 번호를 두 번 앞질러 바꿨다. 이 두 줄을 파일 맨 위에 넣은 뒤 멈췄다.
> **상태 파일에 규칙을 적는 것이 실제로 효과가 있다는 관측이다.**

> 그리고 게이트는 이 파일을 검증 수단으로 인정하지 않는다. v1 의 검사 6 이 탐색 경로에
> 이 파일을 넣어서 죽어 있었다 — 계획에 R-ID 를 적는 순간 "검증 수단 있음" 으로 통과했다.
> **계획에 적는 것은 검증이 아니다.**

## 이번 단계 종료 조건

1. 담당 R-ID 가 `REGRESSION.md` 또는 `CHECKS.md` 에 항목을 갖는다
2. 게이트가 exit 0
3. 열린 blocker 0건 (게이트 출력 기준. 손으로 세지 않는다)
4. 사용자에게 보이는 동작을 사람이 직접 확인했다
5. 겹치는 회귀 항목을 재확인하고 확인 해시를 갱신했다
6. green 태그를 찍었다
